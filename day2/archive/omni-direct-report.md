# Day 2 下一轮：有声视频直传对照与复盘

实验日期：2026-10-20。此轮只研究“视频中的哪里适合暂停并让玩家参与”，不推荐固定小游戏，也不生成 JS。原片来源、许可、文件哈希、转换方法及**首次调用前**的人工声画标注见 [素材与标注](omni-source-annotation.md)。主素材是 [Evworo 的 *Table tennis.webm*](https://commons.wikimedia.org/wiki/File:Table_tennis.webm)，许可 [CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/)。[有声版](../../mp4-example/S06_有声乒乓球.mp4)与[无声版](../../mp4-example/S06_无声对照.mp4)具有相同的视频流；[无人走廊](../../mp4-example/S04_无人走廊.mp4)是负样本。

## 固定条件和核验

- 模型 `qwen3.8-omni-flash`，直接传视频，`fps=2`；固定文件，不在运行间重新编码。先测 [v6](../../prompts/v6.txt)，再测 [v7](../../prompts/v7.txt)；每版有声 3 次、无声 3 次、走廊 1 次，共 **14 次成功调用**。没有发生 JSON 模式兼容性失败，也没有触发回退。
- 请求均采用 `response_format={"type":"json_object"}`。每份 JSON 留有实际提示词全文、视频 SHA-256、请求选项、API 尝试、原始响应、用量和解析结果。
- 有声主片每次报告视频 Token `13664`、音频 Token `156`；无声主片视频 `13664`、音频 `0`；走廊视频 `4842`、音频 `156`。用户已亲耳确认主片的击球声与画面对应。Token 为**输入模态存在性**证据，不证明模型正确理解了声音。所有 14 次生成的候选均标为 `source=visual`，没有一个声称 `both`，因此无法据此证明音频改善了打点。
- 事前冻结的 9–10 秒动作前窗口和用户**事后**认可的 1.5、19.5 秒可玩位置分开评价。后者不能反写成事前真值，但同样不能因为不在唯一的事前窗口里就被判为不可玩。产品运行不需要人工标注；人工只用于此次效果评估。

## 判断

1. **位置层面有部分成果。** v6 有声三次中，1.5 秒出现 **2/3**；用户回看认可其可玩性，19.5 秒也被认可但只出现 **1/3**。v7 有声三次分别为空、15.5 秒、空，没有重复位置。位置的可玩性与模型给出的动作叙述应分开看。
2. **严格按事前验收，未达标。** 冻结的 8.75–9.50 秒窗口在 v6/v7 的有声各三次中均未命中；仅 v6 无声一次给出 9.5 秒，v7 无声一次给出邻近边界的 8.5 秒。更重要的是，不止一条候选含有可回看即不成立的准备姿态描述，因此不能声称“所有保留候选均有真实画面依据”。
3. **加入声音没有显著改善证据。** 有声输入确有正数音频 Token，主片击球声也经人工听轨确认；但所有候选都只标 `visual`，有声组并没有更稳定命中事前窗口。无声组还出现“声效”表述，说明即使格式有效，模型仍可能补出未提供的模态信息。
4. **v7 的收紧使输出更少，不等于更可靠。** 有声组空候选从 v6 的 1/3 变为 v7 的 2/3；唯一 v7 有声候选的三段时序证据也不充分。两个版本的走廊均为空，说明负样本约束在这次素材上有效，但样本量只是一条。

结论：Demo 已能直传有声视频、把候选点定位到原片，并保留完整实验记录；v6 找到了用户认可且重复出现的 1.5 秒位置。但当前不能把模型的具体证据文字直接当作可信事实，也不能宣称提示词打点已稳定通过验收。下一轮若继续优化，优先让模型引用更少、更可观察的画面事实，并对候选证据单独做核实；不要以更长的三段叙述代替真实依据。

`python -m unittest discover -s demo/tests -q` 覆盖请求 JSON 模式与受限回退、候选来源与时间范围、音频 Token 缺失、空候选、旧记录兼容和页面点击回看；该命令不调用云端模型。
