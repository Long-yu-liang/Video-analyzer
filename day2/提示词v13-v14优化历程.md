# Day 2 视频交互分析提示词：v13–v14 优化历程

本文承接 [v2–v12 优化历程](提示词v2-v12优化历程.md)，重点说明两次变化：**v13 将视频识别和机会发现拆成独立阶段；v14 在这套流程上改进事件观察范围与长视频处理。** 项目目标仍是让模型说明发生了什么、哪里适合玩家参与，以及为什么适合；具体小游戏规则和 JS 生成留待后续。

## 一、v13：从一次完成所有判断，改为先识别、再寻找

### 为什么改变策略

v12 已能提出多个候选，但事件识别与交互构思在一次调用中同时完成。出现错误时，往往难以判断：是模型看错了动作，还是看懂了画面却提出了不合适的参与方式。例如，人物是否已经出手属于画面识别；此时让玩家投篮、传球或移动是否合理属于机会判断。

v13 把两个问题拆开，让第一阶段结果可以先展示和回看，再决定哪些画面进入第二阶段。这里使用的是**同一个** `qwen3-vl-plus` **的两次独立调用**，不要求两个不同型号的模型。

流程为：

> 视频 → 详细可观察事件与代表时间 → 回看、勾选事件 → 对应原画面与事件背景 → 玩家参与机会与理由 → 点击回看

### 第一阶段：让事实记录服务于后续判断

[v13/events.txt](../prompts/v13/events.txt)只负责说明画面发生了什么，不直接提出交互点。它要求区分接近、取得物体、调整朝向、准备、执行、结束等状态，避免把一连串动作概括成一句“人物一直在活动”。

每条事件记录起止时间、`observation_s` 代表画面时间、描述、画面依据和不确定性。代表时间的意义是：后续可以取出这一时刻的真实画面，检查模型描述的状态是否存在。描述只应覆盖截至该时间已看到的内容，后续变化另列事件。

这一阶段的“详细”，重点在于把行为状态交代清楚。人物身份、精确距离、不可辨认的号码或未看清的结果，会增加输出却不一定帮助寻找参与机会。

### 第二阶段：从当前画面出发，开放地设想玩家行为

[v13/opportunities.txt](../prompts/v13/opportunities.txt)接收带 ID 的画面及事件背景，回答“如果现在暂停，玩家可以做什么，为什么适合”。它允许同一画面提出多个不同机会，也允许空数组。

例如，画面里人物已经接到一个物体，可以设想让玩家决定如何使用或转交；厨房里器具靠近容器，可以设想控制开始倾倒的时机。**实拍视频后来是否执行这个建议，不再是候选成立的前提。** 但建议仍须与当前可见的人、物或方向相连，不能把设想写成视频已发生的事实。

第二阶段只输出画面 ID、机会和理由。程序把 ID 映射为实际抽取画面的时间，因此定位不再依赖第二个模型重新猜一个秒数。这个时间指向真实发送的画面，但画面中的主体和动作是否识别正确，仍需回看。

## 二、v14：优化事件描述，并让长视频能够完整处理

### 第一轮优化：解决详细描述写不完的问题

S07 前 58 秒的 [v13 失败记录](../results/qwen3-vl-plus/v14/S07_篮球比赛_前58秒__direct__20261021T142532931720__1c981f2e7e8fe47e91061d6bce782c70.json)虽然存放在 `v14/` 目录，实际调用的仍是 `prompts/v13/events.txt`。它达到每次请求 4096 输出 tokens 的上限，`finish_reason=length`，原文写到约 37 秒时截断，无法通过第一步校验。

 v14 因此强调按有意义的变化记录、减少重复和无关细节。同时程序对超过 25 秒的视频分段：S07 送入 0–20、19–40、39–58 秒三段画面，再将各段时间换回原片位置。这是**提示词调整与程序分段共同作用**。

[早期 v14 运行](../results/qwen3-vl-plus/v14/S07_篮球比赛_前58秒__direct__20261021T145025939510__7ee190fd0ec4f2499473e422ccd356aa.json)的三段均以 `stop` 结束，分别输出 1,295、1,137、1,319 tokens，合并得到 28 条事件。它证明这次分段完成了全片处理，但仍出现片头事件错位及边界附近重复描述。

### 第二轮优化：回到通用的观察目标

随后对 [当前 v14/events.txt](../prompts/v14/events.txt)进行通用化改写。它保留 v13 的第一阶段职责，同时更明确地说明：事件识别是为了给后续的动作前机会、可见选择和关键物体相关机会提供信息。

| 观察方向 | 当前 v14 如何展开 | 为第二阶段保留的信息 |
| --- | --- | --- |
| 行动前后 | 分开观察接近、准备、执行、持续和结束；不要求人物静止 | 此刻哪些操作尚可参与，哪些行为已经发生 |
| 可见选择 | 记录不同方向、对象、路径以及观察、停顿、试探、转向 | 画面实际提供了什么可选对象，不编写内心决定 |
| 物体与环境 | 区分背景存在、镜头突出、角色注意、拿取和状态变化 | 为什么某个物体在这个时刻值得关注 |
| 人物互动 | 记录靠近、递交、接收、示意、回应、配合或离开 | 可以参与的关系和行为，不补写对话或动机 |
| 日常及局部画面 | 主体可以是手、工具、车辆、动物或被操作的物体 | 不因没有完整人物、动作不剧烈而漏掉机会 |

提示词用倾倒、做饭、吃饭、驾驶、路径分岔、发现物体等例子解释观察方法。这些是跨题材的说明性示例，并非当前视频的事实，也不是要求模型强行凑齐的类别。准备或发现状态即使没有拍到后续执行，也应保留为事件。

v14 继续要求事件不能太粗，以免漏掉关键准备画面；也不能机械地每秒拆一条，以免重复堆积。**当前 v14 没有修改第二阶段提示词，机会分析仍使用 v13/opportunities.txt。**

## 三、v13 与 v14 的区别

| 维度 | v13 | 当前 v14 |
| --- | --- | --- |
| 核心策略 | 建立“事件识别→审核→机会发现”的两阶段流程 | 延续两阶段，优化第一步的通用观察范围与完整处理能力 |
| 第一阶段 | 详细记录行为状态及代表画面 | 更系统地覆盖行动、选择、物体、环境和人物互动 |
| 题材适用 | 已使用通用状态变化表述 | 更明确支持日常、剧情、探索、出行及局部主体，减少球类导向 |
| 长视频 | 一次整段识别，可能输出截断 | 程序分段并合回原片时间，截断时可缩短片段重试 |
| 第二阶段 | 基于画面与事件开放提出参与机会 | 继续使用同一份 v13 机会提示词 |
| 机会定位 | 模型引用画面 ID，程序赋予画面时间 | 沿用原机制，先完成片段到原片的时间换算 |
