# 任务：为已审核的交互点推荐一种预设小游戏
输入包含一份封闭的小游戏目录，以及若干带 point_id 的交互点。每个点附有参与机会、理由、截至该画面的当前事件，以及一张原片画面。只从目录的 id 中为合适的点选择一种玩法，并说明这个画面为什么适合这种操作。

这是玩法推荐，不是重新寻找交互点，也不生成 JavaScript。不要输出秒数、分数、关卡参数或代码。成功和失败只描述玩家这次操作是否完成，不要编写视频里没有拍到的得分、对白或后续剧情。

某个点如果目录中的玩法都不合适，就不要为它输出推荐。允许 recommendations 为空数组，不要为了覆盖每个 point_id 而勉强推荐。机会和理由里的文字尚未核实，以所附画面为准；不要把先前事件或字幕写成当前画面里必有的物体。每条 fit 必须连到该画面中可见的人、物、姿态或方向。

持球、球刚到手、手臂尚未抬起，也可以是 timing 或 hold_release，不要只因为还能写出「投、传、运」就改成 choice。短滑换道用 swipe，把看得见的物体移到落点才用 drag。下面的片段都是假设，不是当前视频的事实。

同一 point_id 最多一条。只使用输入中确实存在的 point_id，game_id 必须是目录里的 id。只返回合法 JSON 对象，使用标准双引号，不要 Markdown：
{"recommendations":[{"point_id":"p1","game_id":"choice","fit":"这个画面的可见线索为什么适合该玩法","player_goal":"玩家要达成什么","player_action":"玩家具体做什么","success":"怎样算完成这次操作","failure":"怎样算未完成","feedback":"成功或失败时玩家看到什么"}]}

# 假设片段
这些只示范画面和玩法的对应，不要把它们写进当前视频的 fit。

- 投篮时机：球已在手里，篮筐可见，短窗口内按下出手。game_id=timing。玩家目标是卡准出手。
- 剧情三选一：画面上同时有三个看得见的下一步，标成 A、B、C。game_id=choice。玩家目标是点中一个。
- 做饭配菜：台面上有几种食材，选出组成这餐的几样，不是把每样拖进锅。game_id=choice。
- 开车躲避：障碍靠近时点按一次躲开。game_id=timing。若改为把车拖进一侧空档，才是 drag；左右短滑换道则是 swipe。
- 点击关键物：信、开关或门把手被镜头突出，点中它。game_id=tap_object。
- 倒水对准：把壶口拖到杯口再倾倒。game_id=drag。
- 连点发力：推门、冲刺或持续用力，限时内重复点击。game_id=mash。
- 接球时机：球飞到身前的一瞬间按下接住。game_id=timing。这和拿到球之后选择传给谁不同。
- 传球给谁：几名队友同时可见，选择把球传给哪一个。game_id=choice。
- 选路或选门：岔路、两扇门或两个通道都看得见，选一个进入。game_id=choice。
- 食材入锅：把台面上的食材拖进锅里。game_id=drag。配菜是 choice，入锅是 drag。
- 节拍按下：动作或节拍落到点上时按一下。game_id=timing。
- 指出目标：在几个人或几个物体里点中要找的那一个。game_id=tap_object。
- 拨开遮挡：把帘子、盖子或信纸拖开。game_id=drag。
- 拿到球后的出手：球刚到手里，手臂尚未完全抬起，仍在短窗口内按下出手。game_id=timing。若要按住、到最高点再松开，则是 hold_release。同一帧若改成选择传给谁，才是 choice。不要因为写得出三个分支就排除 timing 或 hold_release。
